# CLAUDE.md — Restaurant POS

Guide for making changes and upgrades to this project. User-facing documentation (install,
printing, data folders, troubleshooting) is in `README.md`. This file covers how the code is
organized, the rules it follows, and the steps for common changes.

## What this is

Fully **offline** restaurant POS desktop app: Electron 44 + React 19 + TypeScript 6 (strict) +
Vite 8 (Rolldown) + Tailwind CSS 4 + Zustand 5 + electron-store 11 + i18next.

- **Bangla (`bn`) is the default language**; English (`en`) is the other one. Every UI string,
  menu item, receipt and KOT is bilingual.
- There's no backend and no network use at runtime. Remote requests are blocked and the CSP
  forbids remote origins.
- Pages: POS · Tables · Orders · Reports · Shift · Settings. Thermal printing (80/58 mm), sales
  reports with charts, JSON backup/restore, CSV export.
- Git: branch `main` on https://github.com/polashmiya/restaurant-pos-electron (remote `origin`).

## Commands

```bash
npm run dev          # Vite + Electron with hot reload (data: %APPDATA%\Restaurant POS Dev)
npm run verify       # typecheck (3 projects) + lint + unit tests + build — run before finishing
npm run test         # Vitest (jsdom, threads pool)
npm run test:e2e     # builds, then Playwright drives the real Electron app
npm run dist:win     # installer → release/<version>/Restaurant POS-Setup-<version>.exe
node scripts/menu-images.mjs candidates|sheets|apply   # demo menu photo pipeline (dev only, needs internet)
```

Single test: `npx vitest run tests/utils/reports.test.ts` · single e2e: `npx playwright test e2e/reports.spec.ts`
(run `npm run build` first — e2e tests launch the built `dist/`).

Useful env vars: `POS_USER_DATA_DIR=<dir>` (isolated data folder), `POS_PRINT_TO_PDF_DIR=<dir>`
(every print job becomes a PDF — used by e2e tests).

## Definition of done

1. `npm run verify` passes (no TS errors, no lint errors, all tests green).
2. UI, IPC, printing or startup changed → also `npm run test:e2e` (11 tests; ~35 s).
3. New user-visible text exists in **both** `src/i18n/en.ts` and `src/i18n/bn.ts`.
4. Persisted data shape changed → schema migration + test (see recipe below).
5. New behaviour covered by a unit test; README updated if a user-visible feature changed.
6. For visual changes, build and look at it (screenshot the running app) in dark **and** light
   theme, Bangla **and** English, at 1366×768.

The main process imports shared code from `src/` **only** through files listed in
`tsconfig.node.json` → `include` (types, config, data, and a few utils). Anything the main process
needs must be DOM-free and added to that list.

## Rules the code follows

- **Persist first, then update state.** Workflows write through `getStorage()` and only then
  commit to Zustand, so the screen always shows saved data. Order-related writes go through
  `runExclusive()` (`services/persistQueue.ts`). Tasks must never call it re-entrantly.
- **Derived values are never stored.** Cart totals come from `calculateOrderTotals()`. Report
  figures are computed on the fly by `buildSalesReport()`.
- **Money in integer minor units.** Use `toMinor/fromMinor/sumMoney/roundMoney`
  (`utils/money.ts`). Never add floats directly.
- **All formatting goes through `useFormatters()`** (or `createFormatters()` outside React):
  currency, numbers (optional Bangla digits), dates/times (`bn-BD` / `en-GB`). Never call
  `toLocaleString` ad hoc.
- **All text goes through i18n** (`t('key')`, typed keys). Messages kept in state use
  `message(key, params)` so they re-translate when the language changes.
- **All colors are theme tokens** (`bg-surface`, `text-fg-muted`, `bg-primary`, `bg-chart-1`…).
  The default Tailwind palette is removed, so a raw `bg-blue-500` produces nothing. Table
  drawings use `fill-scene-*` tokens.
- **Look preferences live on `<html>`** and are applied by `applyAppearance()` (`utils/theme.ts`):
  `data-density`, `data-accent` (accent sets in `theme.css`), the root font size (text size:
  everything in `rem` scales, so keep touch targets and chrome in `px`), and `--app-card-scale`
  (card grids use `minmax(calc(<base>rem*var(--app-card-scale)),1fr)`). Anything that should
  look "branded" uses `primary` / `chart-1` tokens so it follows the accent (report charts, native
  controls via `accent-color`, text selection). Pixel-based drawings (the SVG column chart)
  multiply their sizes by `useTextScale()`. `rememberLook()` keeps a copy in localStorage so
  `main.tsx` paints the loading screen in the last theme/accent/size before settings load.
- **Shared building blocks:** `PageHeader` (every page's header bar), `Notice` (inline
  info/warning boxes), `Kbd` (`tone="inherit"` on coloured buttons), `Modal`, `IconButton`,
  `SegmentedControl`. Reuse them instead of copying class strings.
- **All constants live in `app.config.ts`.** App name/version/description come from
  `package.json` (injected as `__APP_NAME__` etc.).
- **Security (do not weaken):** `contextIsolation`, `sandbox`, `nodeIntegration: false`;
  every IPC handler calls `assertTrustedSender` and validates every argument; no remote URLs,
  no `webview`, no new windows; menu images must be `data:image/…` or `images/menu/*.webp`
  (`isMenuImageSource`).
- **Errors:** throw `AppError(kind, translationKey)`; UI actions use `attempt()` (void → boolean)
  or `runAction()` (returns an object or `undefined`), which show a localized toast.
- Dates are **local time**; ranges are `[start, end)`. Use calendar helpers
  (`addDays`, `startOfDay` in `utils/reports.ts`), not millisecond arithmetic.
- Match the surrounding style: logical CSS (`ms-`, `pe-`, `start-`), 48 px touch targets
  (`min-h-touch`), icon-only buttons via `IconButton` (required `label`), dialogs via `Modal`.

## Recipes

### Add or change UI text
Add the key to `src/i18n/en.ts`, then the same key to `bn.ts` (TypeScript fails if one is
missing). `tests/i18n/translations.test.ts` also requires identical `{{placeholders}}` in both
languages, and every Bangla value must contain Bengali script. Pure punctuation or Latin-only
values fail unless allow-listed in that test. Plurals need `_one` and `_other` in both files.
Numbers in strings use `{{count, num}}`.

### Change colors / look
Edit `src/styles/theme.css` (dark block `:root, :root.dark` and light block `:root.light`). For a
new token, add `--c-name` to **both** blocks and map it in `index.css` → `@theme inline`
(`--color-name: var(--c-name)`). Chart colors are `--c-chart-1`, `--c-chart-1-hover`,
`--c-chart-grid`; `chart-1` follows the accent color (set per accent below). The series colors
were contrast-checked (≥3:1 on the card surface); recheck if you change them.
Tunable numbers (timings, limits, sizes) go in `app.config.ts` too — pure geometry and unit
conversions (table drawing, mm↔px) may stay next to the code that uses them.

New **accent color**: add `:root[data-accent='x']` (dark) and `:root.light[data-accent='x']`
blocks to `theme.css` (`--c-primary`, `-hover`, `-text`, `--c-focus`, `--c-chart-1`,
`--c-chart-1-hover`), a `--c-swatch-x` token, the value in `ACCENT_COLORS` (app.config),
`SWATCH_CLASSES` in `settings/AccentPicker.tsx`, and `accentColor.x` translations. Contrast-check
it: white on the button and hover ≥ 4.5:1, accent text on `surface` and `surface-2` ≥ 4.5:1,
focus ring ≥ 3:1. Run the chart color through the dataviz validator per mode
(`validate_palette.js "<hex>" --mode dark --surface "#161a21"`, and `--mode light` on `#ffffff`):
lightness band, chroma floor, ≥ 3:1 on the card. Dark mode needs a lighter step than the button.

### Add a setting
1. Add the field to `AppSettings` / `PrinterSettings` / `UIPreferences` in `src/types/settings.ts`.
2. Add its default in `src/data/defaults.ts`. `mergeWithDefaultSettings()` fills it in for
   existing users automatically; no migration is needed for new settings. For a choice-type UI
   preference, also list its allowed values in `UI_CHOICES` there, so an unknown stored value
   falls back to the default.
3. Add a control in the matching `src/components/settings/*Settings.tsx`, saved through
   `useSettingsStore().updateSettings(patch)`. Add translations.

### Change the persisted data shape (schema migration)
1. Bump `APP_CONFIG.storageSchemaVersion` in `src/config/app.config.ts`.
2. Add `MIGRATIONS[newVersion]` in `src/data/initialize.ts`. It must be **immutable**: return new
   objects/arrays for changed collections. `runMigrations()` detects changed collections by
   reference and writes them back. Never touch user-customized records (see v2, which adds photos
   only to untouched demo items).
3. Update validators (`src/data/validators.ts`) if records gained or lost required fields.
   Backups are validated with them.
4. Test in `tests/data/initialize.test.ts`: old data is migrated, and running again changes nothing.

### Add a new persisted collection
Add it to `StoreSchema` (`src/types/storage.ts`), `STORE_KEYS` and `STORE_KEY_KIND`
(`src/data/storeKeys.ts`), `KEY_GROUP` in `electron/main/store.ts` (which JSON file it lives in),
initialization/repair in `prepareStoreData()`, backup handling in `src/data/backup.ts`, and
hydration in `services/bootstrap.ts → applyStoreData()`.

### Add a page
`PageId` in `src/store/uiStore.ts` → `case` in `components/layout/AppShell.tsx` → item in
`components/layout/Sidebar.tsx` (`MAIN_ITEMS`) → `nav.<page>` translation. For a shortcut: add it
to `KEYBOARD_SHORTCUTS` (app.config), `useKeyboardShortcuts.ts` (the `isShortcut` list and the
`switch`), the list in `settings/AboutSettings.tsx`, the `shortcuts.*` translations, and README.
Page layout convention: `<PageHeader title description actions>{filters}</PageHeader>`
(`common/PageHeader.tsx`), then a scrollable body (`min-h-0 flex-1 overflow-y-auto p-6`).

### Add a dialog
Add a variant to the `AppModal` union (`uiStore.ts`), a `case` in `layout/ModalHost.tsx`, and
open it with `useUIStore().openModal({ type: … })`. Build it on `common/Modal`, which provides
focus trap, Esc to close and a footer. Confirmations use `confirmAction({ title, message, tone })`.

### Add an IPC channel
1. Name it in `electron/shared/ipcChannels.ts`.
2. Type it in `electron/types/electron.d.ts`.
3. Expose it in `electron/preload/index.ts`.
4. Handle it in `electron/main/ipcHandlers.ts` via `handle()`, which checks the sender. Validate
   **every** argument with the `require*` helpers.
5. Add it to the exact API allow-list in `e2e/security.spec.ts`, plus a "rejects bad input" check.
6. Provide a browser fallback in the renderer when `window.electronAPI` is undefined (browser
   preview mode).

### Add a printed document
Create a component in `src/components/printing/` using the `DOCUMENT_CSS` classes from
`printStyles.ts` (`title`, `heading`, `meta`, `num`, `qty`, `strong`, `small`, `c`, `<hr>`) and
`paperClass(paperWidth)`. Take text from its `DocumentContext`, not the UI language. Then:
1. Add a variant to `PrintDocument` (`src/types/print.ts`).
2. Handle it in `services/printService.tsx`: `renderDocumentElement()` (the preview and the printed
   page are the same element), `documentTitle()`, and `documentPrinterKind()` if it goes to the KOT
   printer. Add its PDF name to `documentFileName()` (`utils/fileNames.ts`).
3. Show it with `<PrintDialog document={…} />` (preview, printer, copies, Save as PDF, Print), or
   from a service with `openPrintDialog()` in `services/printActions.ts`. `printPerSettings()`
   there shows how the KOT and bill buttons respect *Print without dialog*.
The main process only ever prints **silently** to a named printer. Printer choice, copies and
preview belong to the app's dialog.

### Add a report metric or chart
Compute it in `buildSalesReport()` (`src/utils/reports.ts`; one pass, minor units) and add the
type to `src/types/report.ts`. Render it in `components/reports/ReportsPage.tsx` using
`ChartCard` (give it a `table` for the table-view toggle), `ColumnChart` (single series, keyboard
+ tooltip), `BarList` (ranked bars with direct labels) or `ReportStatTile` (KPI + delta). Chart
rules: one hue per single series, bars ≤24 px with a rounded top, text in text tokens (never the
series color), no dual axes. Add tests in `tests/utils/reports.test.ts`. If the figure belongs
on paper, add it to `SalesReportPrint.tsx` too.

### Menu photos
The demo photos are generated, not hand-edited:
`node scripts/menu-images.mjs candidates <CODES> [--commons-first]` downloads options into
`scripts/.image-cache` (gitignored) and builds contact sheets. Put the chosen indexes in
`scripts/menu-image-choices.json`, then run `… apply`. That writes `public/images/menu/*.webp`,
`src/data/imageCredits.ts` and `CREDITS.md`. Use only commercially usable licenses
(CC0 / PD / CC BY / CC BY-SA). Seed items pick up photos through `getBundledMenuImage(code)`.

### Demo data
`src/data/seed.ts` holds 8 categories, 50 items (`item-001`…, codes like `BUR-001`) and 20
tables. Seed runs only when a collection never existed. Sample sales
(`utils/sampleSales.ts`, deterministic PRNG) are flagged `sample: true` on orders and shifts and
cover the `reports.sampleDays` days **before today**.

### Rebrand
Name/version/description: `package.json`. Colors: `theme.css`. Icon: `build/icon.png`
(`npm run icons`). Installer id and copyright: `electron-builder.yml`. Restaurant defaults:
`src/data/defaults.ts`.

## Upgrading dependencies

- After any upgrade: `npm run verify && npm run test:e2e`, then `npm run dist:win` and launch
  the unpacked app (`release/<v>/win-unpacked`) once.
- **Electron major:** keep `sandbox`/`contextIsolation`; the preload must stay CJS
  (`vite.config.ts`); re-run `e2e/security.spec.ts`; check the print pipeline
  (`printManager.ts`: hidden window, page height measured from `body`).
- **Vite / vite-plugin-electron:** main output is ESM `dist-electron/main/index.js`, preload
  is `dist-electron/preload/index.cjs`, and `electron-store` stays external.
- **Tailwind 4:** configuration is CSS-first (`index.css` `@theme inline`, `@custom-variant dark`
  and `compact`); there is no `tailwind.config.js`.
- **TypeScript 6:** there's no `baseUrl`; paths are `"@/*": ["./src/*"]` in every tsconfig.
- **lucide-react:** use **canonical** icon names (`Trash`, `CircleCheckBig`, `TriangleAlert`…).
  Check existence in `node_modules/lucide-react/dist/lucide-react.d.ts` before using a new one.
- **i18next:** keys are typed through `src/i18n/i18next.d.ts`; the custom `num` formatter is
  registered in `initI18n()`.

## Gotchas (learned the hard way)

- `cn()` (`utils/cn.ts`) only joins strings; it does **not** merge Tailwind classes. Passing
  `w-auto` to something whose base has `w-full` leaves both, and CSS order decides. Write
  explicit classes instead of overriding shared ones like `controlClassName`.
- ESLint `react-hooks/set-state-in-effect`: don't call setState synchronously inside an effect.
  Derive during render or set it from async callbacks.
- ESLint `react-refresh/only-export-components`: `.tsx` files export components only. Put helpers
  and constants in `.ts` modules.
- JSX needs a `.tsx` file (that's why `printService.tsx` has that extension).
  Watch for import cycles between services; shared runners live in `actionRunner.ts`.
- `ResizeObserver` doesn't exist in jsdom; `useElementWidth` falls back to 640 px.
- Vitest must use `pool: 'threads'` (forks time out on Windows). `posStore` is a singleton, so
  reset the draft in `beforeEach`. Use `createMemoryStorage()` + `setStorageAdapter()` and
  `failOn('setMany')` to simulate disk errors.
- e2e selectors are in **Bangla** (the default UI language). Use `exact: true` or scope to
  `getByRole('dialog')` to avoid strict-mode collisions. The first key press right after launch
  can be lost, so wrap it in `expect(async () => …).toPass()`.
- When writing files from PowerShell, don't embed raw control/BOM characters. Use escapes such as
  `'\uFEFF'` in source, and avoid control-character regex ranges (ESLint `no-control-regex`).
- Never call `webContents.print({ silent: false })` on a hidden window. On Windows 11 the
  system dialog shows "No preview available", and its callback may never fire, so the Print button
  spins forever and the hidden window leaks. Print silently. Preview and printer choice live in
  `PrintDialog`.
- VS Code terminals set `ELECTRON_RUN_AS_NODE=1`, which makes `electron.exe` behave like plain
  Node. Unset it before `npm run dev` / `npm run test:e2e` (`env -u ELECTRON_RUN_AS_NODE \u2026`).
- Promise-based dialogs (`openPrintDialog`) settle by watching `uiStore.modalStack`, not from an
  effect cleanup: StrictMode runs cleanups on mount in development.
- Order numbers (`ORD-YYYYMMDD-####`) come from `generateOrderNumber()`, which skips numbers that
  already exist. Never derive them from array length.
- Completed orders are stored in monthly files (`orders/pos-orders-YYYY-MM.json`). Write them via
  `append` (one order) or `setMany({ completedOrders })` (whole history).

## Working agreements

- Keep the app offline-only and bilingual; never add runtime network calls or remote assets.
- Don't file this project's work to DevOS or any external tracker unless the user asks.
- Work through multi-phase requests without pausing for permission between phases. Verify
  (typecheck + tests) after each phase.
